## Детали

### 2. Четыре модели — ДА

Одна и та же задача: один текстовый фрагмент, три вопроса (`bool` + `choice` + `score`), `return_top: 1`.

### 5. Живучесть `HTTP 400` — ДА (тест, не живой прогон)

Живая safety-блокировка на Polza не воспроизводится (пробы 2026-11-22: токсичный ввод классифицируется, `content_blocked` не приходит). * 5 вызовов `decide` (исходный + две половины + изоляция + успешная половина);
* статус `partial`, `items_processed = 3`, `items_blocked = 1`;
* в SQLite: `ok1 → ok`, `toxic → safety_blocked`, `ok2 → ok`, `ok3 → ok`; ответы остальных сохранены.

В регрессе `npm test` есть тот же сценарий: `safety-блокировка даёт partial: элемент изолирован, остальные сохранены` (`src/core/engine.test.ts`).

Независимое evidence симуляции: `fixtures/dod/safety-evidence.json` — `runId`, `status`, `stats`, `providerCalls = 5` и `itemStatuses` (`ok1/ok2/ok3 → ok`, `toxic → safety_blocked`).

* **Этап 1:** `fixtures/dod/data/session-stage1.jsonl` (12 синтетических шагов, проекция `skeleton`, префильтр, 1 вопрос `problem_score`), прогон `run_20261122_185847_04db`, статус `completed`, 12/12 обработано, 2 681 входных токенов, 0.01319713 ₽.

* **Этап 2:** `source: { type: "from_run", run_id: ..., where: ..., context_window: 2, projection: "full" }`, прогон `run_20261122_185849_d039`, статус `completed`, **6 элементов** (только цели, не 12), 14 458 входных токенов, 0.07116903 ₽. В БД `parent_run_id = run_20261122_185847_04db`.
* **Соседи и склейка:** `decide_query inspect` запросил три цели (`step_002`, `step_004`, `step_006`) и показал непрерывный эпизод из 12 шагов (пересекающиеся окна ±2 склеены), в тексте есть маркеры `--- step_NNN (seq N) ---` и `[target]`. * **Вопросы только на целях:** ответов в SQLite Этапа 2 — 6 (по одному на цель), а не 12.
