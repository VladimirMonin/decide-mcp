# Тестирование изменения

## Ответственность и текущее состояние

Инструкция регулирует выбор, изоляцию, запуск и интерпретацию проверок. Она не даёт права на рабочие данные, сеть, платные вызовы или выпуск. Приоритеты и границы доказательства — в [стратегии тестирования](../foundation/testing-strategy.md).

**Runner настроен:** Node.js 25.8.1, `tsc` + `node --test`. Проверенные команды на 2026-11-22:

- `npm run build` — сборка TypeScript;
- `npm test` — сборка и офлайн-тесты по `dist/**/*.test.js` (13/13);
- `npm run smoke` — платный живой smoke четырёх моделей Polza, в `npm test` не входит.

Версия Node и фактические команды фиксируются здесь при изменении runner-а.

## Практический порядок

1. **Назови сценарий и инвариант.** Что должен получить пользователь или агент, что считается отказом, кто владелец и потребитель. Для `decide-mcp` типичный инвариант — компактный ответ, сохранённый прогон, безопасный путь или паритет шлюзов.
2. **Найди существующую проверку.** Выбирай по impact и цене ошибки, а не по числу изменённых строк. Не создавай второй продукт в тесте.
3. **Выбери границу.** Unit для чистых правил (`schema`, `tokenizer`, `batcher`, `prefilter`). Integration для `sources/store/query` на временном дереве и временной БД. Scenario для MCP через stdio-клиент. Живой smoke — вручную и отдельно.
4. **Изолируй до импорта.** Назначь временные `DECIDE_DB_PATH` и `DECIDE_ALLOWED_ROOT`, фиктивные ключи и локальный HTTP-стаб для провайдера. Не читай реальные `.env`, `.decide-mcp/runs.sqlite`, пользовательские логи и сессии. Зарегистрируй cleanup сразу после acquire, включая частичный setup.
5. **Выполни минимальный случай, затем affected pack.** Сначала конкретный файл или тест, затем затронутая группа. Полный suite — только при обоснованной широкой границе.
6. **Проверь существенные отказы.** Для батчера — `HTTP 400` и изоляция одного элемента; для store — запись и повторное чтение; для `dry_run` — ноль HTTP-вызовов; для путей — выход за корень и исключённые каталоги; для `from_run` — склейка окон. Oracle проверяет наблюдаемый результат, а не только число вызовов.
7. **Сохрани evidence.** Команда, сырой код выхода, выборка, версия Node, входные данные, подмены, skips и остаток. Первый отказ сохраняется, assertion не ослабляется.
8. **Переиспользуй неизменное.** После изменения схемы, mapper-а, fixture или артефакта повтори affected и недоказанные случаи.

## Изоляция и данные

- Временный корень теста — единственный источник файлов; цель «вне корня» — соседний временный каталог.
- SQLite-файл — временный; соединение закрывается до удаления. Открытый handle на Windows блокирует очистку.
- HTTP-стаб слушает `127.0.0.1` на свободном порту; базовый URL провайдера переопределяется только в тесте.
- Fixture с реальными ответами API хранится без ключей, заголовков авторизации и идентификаторов аккаунта. Стоимость и `usage` можно сохранять.
- Временные артефакты имеют владельца и срок; они не становятся постоянной базой задачи.

## Платные проверки

Живые вызовы Polza AI/OpenRouter разрешены без отдельного согласования.

- Помечай `[PAID]` в команде, выводе и отчёте.
- Записывай `usage.input_tokens`, `output_tokens` и `cost_rub`.
- Сначала бесплатный каталог или `dry_run`, затем минимальный набор моделей.
- Не повторяй платный прогон без причины; повтор после исправления бага — причина, укажи её.
- `npm test` остаётся офлайн; smoke запускается отдельно.

## Ограничения

- Написанный тест не равен выполненному; static-вывод не равен пользовательскому маршруту.
- `exit 0` с нужным skip не является PASS этого сценария.
- Coverage и линтер не доказывают архитектуру и качество ожиданий.
- Живые вызовы разрешены, но помечаются `[PAID]` и не входят в `npm test`.
- Не читай личные secrets, логи и БД ради синтетической подготовки и не удаляй чужие результаты.

## Достаточность и обновление

Согласованные критерии наблюдаются, риски изменённой границы проверены, команды и сырые коды сохранены. Независимая приёмка не требует повторять неизменённые дорогие проверки.

Обновляй инструкцию при принятом изменении runner-а, команд, изоляции, fixtures или уровней evidence. Синхронизация команды не разрешает отключить защиту или расширить доступ. Для проекта нужны только применимые фрагменты стратегии и короткий итог проверки.
