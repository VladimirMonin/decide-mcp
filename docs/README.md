# С чего начать

`decide-mcp` — универсальный движок анализа кода, логов, тестов и агентских сессий на decision-моделях. Ядро само читает данные с диска, режет их на безопасные батчи, сохраняет сырые вероятности в локальный SQLite и возвращает основному агенту только сводку и ограниченный топ. Быстрый старт, `.env` и подключение MCP — в [корневом README](../README.md).

**Состояние репозитория:** есть каркас и Шаг 0 для Polza AI. `npm run build`, `npm test` (13 тестов) и `npm run smoke` (4 модели) прошли 2026-11-22. MCP-сервер, батчер, store, engine и адаптер провайдера ещё не реализованы; OpenRouter, safety- и overflow-поведение не проверены.

## Порядок первого чтения

1. [Архитектура](architecture/system.md) — понять границы системы и хранение.
2. [Контракты](architecture/contracts.md) — увидеть точные схемы и три MCP-инструмента.
3. [Провайдеры и модели](architecture/providers-and-models.md) — настроить шлюз, лимиты и батчер.
4. [Рубрики и воронки](guides/ru/rubrics-and-funnels.md) — научиться формулировать вопросы.
5. [Кукбук](guides/ru/cookbook-use-cases.md) — свериться с проверенными паттернами.
6. [План MVP](plans/mvp-scope.md) — увидеть объём и критерии готовности.

Правила диагностики и проверок читаются по trigger, а не целиком перед каждой правкой.

## Актуальность

Требование, реализация, план и выполненная проверка различаются. `status: draft` у политик и инструкций означает, что текст ещё не подтверждён полной реализацией. Дата редакции не равна сверке кода. Фактический срез Шага 0 — в [отчёте](verification/step0-smoke-2026-11-22.md); после появления `src/` и `tests/` владельцы обновляют затронутые документы в том же логическом результате.

## Поддержка

При существенном изменении автор обновляет затронутое знание либо обосновывает отсутствие влияния. Новый документ добавляется одним обнаружимым маршрутом в этой таблице. Устаревшее заменяется с указанием причины, а не исчезает незаметно.
