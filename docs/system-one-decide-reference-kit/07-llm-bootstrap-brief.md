# 07. Короткий бриф для старта любой LLM (`System One / decide-mcp`)

> **Как использовать:** скопируй этот файл целиком в начало нового чата или в контекст агента, чтобы он сразу проектировал корректные пайплайны на базе decision-моделей без повторных объяснений.

---

## 1. Принцип работы
- **System One (Decision-модели)** за один прямой проход возвращают **только вероятности, категории, числовые оценки или координаты** (`0` текстовых токенов). Они **не** пишут объяснения и **не** рассуждают пошагово.
- **Разделение труда:** детерминированный скрипт (0 ₽) считает точные факты и режет карточки → **System One** массово фильтрует и оценивает (результаты в SQLite) → **System Two (обычная LLM)** читает только короткую сводку и топ-примеры, формулируя причины и правки.
- **Когда НЕ использовать System One:** если хватает обычного скрипта; если элементов мало (<20–30 коротких); если задача чисто субъективная («угадай настроение пользователя»).

---

| Модель | Цена (Polza / 1M) | Окно | Лимит вопросов (Polza) | Модальности | Примитивы | Главная роль |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |

| **`ms`** (`Microsoft-Decision-1`) | **4,92 ₽** | **33K** | По контексту | Текст (`v1.1`: +фото) | `noul`, `choice`, `score` | **Дешёвый черновой фильтр** коротких строк/логов; **НЕ** для тонких причин (валит в `other`) |

## 3. Примитивы и правила формулировок
1. **`noul` (`predicate`)** — факт да/нет (`0..1`). `0.5` = неуверенность, а не «средний уровень». Стартовые пороги: `>=0.7` да, `<=0.3` нет, `0.3..0.7` — серая зона.
2. **`choice`** — 1 из N категорий. **Обязательно добавляй ключ `other`** (не `none_of_the_above`). Маршрутизируй по `probabilities[chosen]` и отрыву от 2-го места, а не только по имени победителя.
3. **`score`** — упорядоченная шкала (держи **3–5 уровней**, у каждого чёткое описание). Проверяй `confidence`, чтобы не пропустить раскол между краями шкалы.
4. **`box`** *(только `Jev 1.14`, пока не в ядре `decide-mcp`)* — края `{top, bottom, left, right}` в долях `0..1`. **Всегда** ставь рядом `Companion Noul` («есть ли объект?»), иначе `box` вернёт рамку на пустом месте.
5. **Критично:** `question_id` **НЕ передаётся модели** — весь смысл пиши в `instructions` и `criteria`. Общие определения выноси один раз в `guide`.

## 4. Стандартный конвейер (5 шагов)
1. **Проба формата (0 ₽):** проверь 2–3 реальные сырые записи (данные и ключи связки), не верь описаниям.
2. **Нарезка карточек (0 ₽):** клади в карточку всё нужное для суждения (например, пару `требование ↔ результат` или тройку `постановка ↔ воркер ↔ ревьюер`, по 1 элементу памяти на карточку). Не обрезай текст без нужды.
3. **Упаковка вопросов (`Speculative fan-out`):** отправляй все вопросы по карточке в одном запросе; лишние ветки игнорируй в коде. Разбивай широкие критерии на 4–5 узких (`Composite scoring`). Разводи пользу (`helped`) и вред (`caused_friction`), добавляй позитивную ось (`positive_leverage`).
4. **Калибровка перед боем (~1–3 ₽):** проверь рубрику на 4 типах карточек (эталон, явный брак, **«реалистичная ловушка»** — красивый текст без 1 условия, инверсия вины) и сравни 2 модели через `compare`. Делай `dry_run: true`.
5. **Воронка и финал:** Слой 0 (локальные теги, 0 ₽) → Слой 1 (`skeleton`, `gemini`/`ms`, отсев 80%) → Слой 2 (`from_run` с окном ±2, `jev`/`gemini`) → финал System Two строго по `aggregate` и топ-10 `inspect`.

---

## 5. Стоп-лист из 8 антипаттернов
1. Не оценивай «ясность» длинного текста одним `score` (эффект красивой формы) — добавляй прямой `noul` на сверку конкретного факта/условия.
2. Не склеивай 3 правила в один `noul` и не мешай пользу с вредом в одну шкалу.
3. Не переноси числовые пороги между моделями без калибровки (`0.8` у `jev` ≠ `0.8` у `gemini`).
4. Не отправляй приватные данные в облако, чтобы спросить «есть ли тут утечка» — проверяй локально до API не только свои секреты и пути, но и **чужие ПД** (ФИО, телефоны, почты, реестры третьих лиц), плюс глазами по экранированным путям (`C\:\`) и цитатам переписки в `reasoning`.
5. Не проверяй `rework_cause` («кто виноват») на карточках без реального сбоя/возврата.
6. Не гоняй крупные окна (>32K) через `jev` — потеряешь элементы и переплатишь за батчи; для них бери `gemini`.
7. Не считай `cost.total = 0` бесплатной моделью — проверяй сырой `usage` (`input`, `cacheRead`, `output` отдельно).
8. Для «слепого» аудита всегда запускай свежего субагента с нейтральным путём без слов-триггеров и запретом читать сырой лог в обход `decide-mcp`.
