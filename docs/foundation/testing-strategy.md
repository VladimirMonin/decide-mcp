# Стратегия тестирования

## Назначение и приоритеты

Тест обнаруживает неправильный пользовательский результат, а не подтверждает количество кода. Простые наблюдаемые ожидания предпочтительнее второй реализации продукта в fixture. Coverage показывает, где не выполнялись строки и ветви; зелёный процент не доказывает нужный oracle, production wiring или правильную архитектуру.

Критические результаты проекта:

1. **Контекст основного агента остаётся компактным.** `decide_run` возвращает сводку и ограниченный `return_top`, а не сырые элементы.
2. **Прогон не теряется.** Все завершённые батчи и сырые вероятности записаны в SQLite; сбой одного батча даёт `partial`, а не потерю остальных.
3. **`dry_run` бесплатен.** План строится без единого HTTP-запроса и без записи прогона в БД.
4. **Граница путей держится.** Источник вне `DECIDE_ALLOWED_ROOT` отклоняется, а `.git`, `node_modules`, `dist` и бинарные файлы не попадают в выборку.
5. **Паритет шлюзов.** Один и тот же `decide_run` работает на `DECIDE_PROVIDER=polza` и `openrouter` без правки кода и рубрики.
6. **Токсичный элемент не валит батч.** При `HTTP 400` батч делится до изоляции проблемного элемента, остальные ответы сохраняются.
7. **Воронка `from_run` работает.** Отбор из прошлого прогона, полная проекция и склейка окон `context_window` не теряют целевые `item_id`.

## Границы доказательства

- **Unit** проверяет правило владельца: валидацию рубрики, токенизацию, раскладку батчей, префильтр, нормализацию ответа.
- **Integration** соединяет реальные `sources`, `store`, `query` на временном дереве и временной БД; внешний провайдер заменяется локальным HTTP-стабом или fake-провайдером на существующем seam.
- **Scenario** проходит настоящий вход MCP: stdio-клиент `@modelcontextprotocol/sdk` вызывает `decide_models`, `decide_run` с `dry_run` и `decide_query`.
- **Live smoke** — ручная проверка реальных ключей и каталога Polza AI/OpenRouter с записью ответов в `fixtures/`. Разрешён без отдельного согласования, помечается `[PAID]`, стоимость фиксируется из `usage.cost_rub`. В автоматический прогон не входит.
- Подмены видны в названии и итоге проверки. Локальный стаб не называется полным E2E, а fixture не доказывает живой протокол.

## Выбор проверки по изменению

| Изменение | Достаточное начальное доказательство | Расширение по риску |
|---|---|---|
| Схема рубрики, `schema.ts` | Валидный пример; границы `choice` 2/255, `score` 2/10, `box` вне MVP; предупреждения линтера | Потребители предупреждений в MCP-ответе |
| Токенизация и `batcher.ts` | 2D-бюджет `элементы × вопросы`, окно 32K у `ms`, `guide` один раз в `state` | Поведение при переполнении и реальные лимиты из Шага 0 |
| `providers/systemone.ts` | `bool → noul`, `confidence`, `usage`, маппинг ошибок на локальном стабе | Паритет двух базовых URL и ретраи `429/502/504` |
| `sources.ts` и безопасность | Временное дерево: файл внутри корня, файл вне корня, symlink/junction наружу, маски `glob`, исключения | `jsonl`-проекции и `from_run` с окнами |
| `store.ts` и `query.ts` | Запись/чтение на временной БД, reopen, `filter/aggregate/inspect/compare` | Потоковая запись при сбое и статус `partial` |
| `engine.ts` | `dry_run` без HTTP и записи; сводка и `return_top`; `partial` при отказе батча | Комбинация с `from_run` и повторным запросом |
| `servers/mcp.ts` | stdio-сценарий: список трёх инструментов, `dry_run`, `decide_query`; stdout — только JSON-RPC | Ошибки и таймауты в клиенте |
| Только поясняющий текст | Ссылки, метаданные, отсутствие противоречий | Machine-consumed команды отдельно |

Начинаем узко и расширяем на затронутую подсистему. Полный suite нужен при широком impact или оговорённой границе выпуска.

## Данные, ресурсы и изоляция

До импорта, сбора или обращения к конфигурации выясняются ранние side effects и задаются собственные временные корни:

- `DECIDE_DB_PATH` указывает на временную БД теста, не на `.decide-mcp/runs.sqlite`;
- `DECIDE_ALLOWED_ROOT` указывает на временное дерево; цель «вне корня» лежит в соседнем временном каталоге;
- ключи провайдеров — заведомо фиктивные; сеть направляется на локальный стаб через переопределение базового URL;
- реальные `.env`, пользовательские логи, сессии и базы не читаются;
- временные файлы и SQLite-соединения закрываются до очистки (на Windows открытый handle блокирует удаление).

Сразу после acquire регистрируется cleanup, в том числе для частичного setup. Освобождаются только собственные соединения, процессы и подписки.

По применимости проверяются ошибка, отмена, повтор без двойного применения, позднее событие после новой операции, сохранность прежнего результата, повторное чтение и возможность следующего действия.

## Интерпретация и завершение

Написано, static review, выполнено, skipped, cancelled и подтверждено через пользовательский путь — разные состояния evidence. Exit 0 с нужным skipped case не закрывает этот сценарий. Сырой отказ сохраняется; дефект приложения, oracle, fixture, данных и окружения различаются по фактам.

Прежний результат переносится только при неизменности владельца, контракта, fixture, окружения и артефакта. Повторяются affected и недоказанные случаи, а не весь suite ради новой даты. Итог содержит выбор проверки, команду, сырой код выхода, версию, наблюдение, подмены и ограничения.

## Владельцы и команды

Владелец стратегии и тестов — ядро; MCP-сценарии принадлежат владельцу сервера. Runner настроен 2026-11-22: Node.js 25.8.1, `npm run build`, `npm test` (13 офлайн-тестов) и `npm run smoke` (платный, 4 модели Polza). `npm run start:mcp` пока целевая команда: сервер не реализован.

После настройки runner-а запиши сюда фактическую команду и ограничения. Не оставляй выдуманный `npm test` в качестве проверенного.
